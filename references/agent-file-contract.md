# AGENTS.md 内容契约

`AGENTS.md` 是项目根目录的 Agent 工作约定。创建或更新时保留托管区外的用户内容，只重新生成托管区。

## 规则文件定位

候选文件名为 `AGENTS.md`、`agents.md`、`agent.md`，比较时忽略大小写：

- 只有一个候选文件时，原地更新它。
- 没有候选文件时，创建标准名称 `AGENTS.md`。
- 有多个候选文件时停止写入，列出冲突并请求用户指定主文件。

规则文件定位以当前项目根目录为边界。外部关联目录单独执行同样的候选检查；父项目不会替外部目录创建或合并规则文件。外部目录的规则继承和编辑边界见 [workspace-boundaries.md](workspace-boundaries.md)。

## 托管区标记

新建或迁移后的文件使用以下边界：

```markdown
<!-- project-agent-bootstrap:managed:start -->
## 1. 项目背景/需求概述
...
## 2. 项目技术框架
...
## 3. 项目目录结构
...
## 4. 项目管理规则
...
## 5. 代码设计与编写原则
...
## 6. 关联工作目录
...
<!-- project-agent-bootstrap:managed:end -->
```

每次运行都重新生成两个标记之间的内容。标记外的标题、备注和用户自定义规则必须原样保留。

旧版文件没有标记时，按固定的五个章节识别现有托管内容，将其包裹到标记中，再执行本次刷新。第六章是新增的关联目录章节；旧文件没有该章节时，在托管区内补充，不把标记外内容移动进去。识别不到完整章节时保留原文并报告待人工确认，不覆盖整个文件。

## 必需章节

### 1. 项目背景/需求概述

从 README、需求文档、构建配置和用户输入提取项目目的、主要业务范围与当前目标。证据不足时写“待补充”，不要编造业务事实。

### 2. 项目技术框架

用一句话概括主要语言、运行时、框架、构建工具和关键存储/中间件。只写能从配置或用户说明确认的内容。

### 3. 项目目录结构

只列项目根目录的一级文件和目录，并为一级目录写一句基本用途。跳过 `.git`、`node_modules`、`target`、`build`、`.venv`、缓存和其他生成目录。

目录用途可以由用户填写，也可以根据根目录 README、构建文件、模块级 README、模块清单和少量明显入口元数据自动推断。低置信度内容标为“待用户补充”，不得递归扫描整个源码树。

### 4. 项目管理规则

记录 Git 远端确认、文档目录、文档清单、进度文件、自动本地提交和变更记录规则。具体模板见 [project-management.md](project-management.md) 和 [git-policy.md](git-policy.md)。

### 5. 代码设计与编写原则

记录最小修改、不过度防御、必要测试、公共接口兼容和牵连变更确认原则。

### 6. 关联工作目录

仅登记已确认的外部关联目录，并记录路径、用途、规则来源和维护方式：

```markdown
## 6. 关联工作目录

| 名称 | 路径 | 用途 | 规则来源 | 维护方式 |
| --- | --- | --- | --- | --- |
| 工作目录 A | `D:/code/project-a` | 业务模块 | 外部 `AGENTS.md` | 单独维护 |
| 工作目录 B | `D:/code/project-b` | 公共服务 | 继承父项目规则 | 按需编辑 |
```

关联目录默认只进行受限分析，不自动编辑。外部目录有唯一规则文件时，编辑遵循外部规则；没有规则文件时，编辑继承父项目规则。多个候选文件或目录不存在时，记录阻断状态，不自动合并、创建或修正外部路径。
