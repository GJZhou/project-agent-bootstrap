# 项目根目录与外部关联工作目录

## 适用范围

当父项目的 `AGENTS.md`、用户当前请求或项目资料明确列出外部关联目录时，使用本规则。外部关联目录是当前项目之外的独立项目边界，不因为被登记就自动成为当前项目的写入范围。

## 受限检索

对每个已登记或由用户明确提供的外部目录，只进行以下只读检查：

1. 检查目录是否存在，并解析为绝对路径。
2. 检查外部目录根目录下的 `AGENTS.md`、`agents.md`、`agent.md` 候选文件。
3. 读取根目录 README、构建文件、模块清单、`docs/`、`progress.md` 和 `.gitignore`。
4. 只列出外部目录的一级文件和目录，跳过明显生成目录、依赖目录和缓存目录。
5. 记录项目类型、一级模块用途、规则来源和待补充信息。

不得递归扫描全部源码，不得发现或修改任意未登记的兄弟目录，也不得因为分析外部目录而创建文件。

外部目录的检查结果使用以下状态：

| 状态 | 处理方式 |
| --- | --- |
| 有唯一外部规则文件 | 外部规则文件是该目录的项目规则来源 |
| 没有外部规则文件 | 继承当前项目根目录规则 |
| 存在多个规则文件候选 | 暂停该目录，报告候选并请求指定主文件 |
| 目录不存在 | 标记为待确认，不创建目录、不修改登记路径 |

## 规则优先级

编辑外部目录内文件时，按以下顺序应用规则：

1. 系统和用户当前指令；
2. 外部目录自己的唯一规则文件；
3. 当前项目根目录规则，仅在外部目录没有自己的规则文件时继承；
4. 本技能默认规则。

外部规则只约束外部目录内的文件，不覆盖父项目自身的规则。外部规则与用户当前要求冲突时，暂停相关编辑并报告冲突。

## 外部目录的分析与编辑

父项目运行本技能时，外部目录默认只分析和登记，不编辑。只有当前任务明确涉及该外部目录的文件时，才进入编辑流程：

1. 按外部目录状态解析规则来源。
2. 将父项目文件与各外部目录文件分组。
3. 对有独立规则的目录，读取并遵循其代码、文档、进度和 Git 规则。
4. 对没有独立规则的目录，继承父项目规则；不因单次代码编辑强制创建外部 `AGENTS.md`。
5. 如果用户明确要求初始化该外部目录的项目规则，才把它作为独立项目执行完整 bootstrap，并创建或维护它自己的 `AGENTS.md`、`progress.md`、`docs/` 和文档清单。
6. 外部目录的配套文档和进度记录保存在外部目录内，不写入父项目的同名文件。
7. 每个 Git 根目录分别决定暂存文件、commit 类型、需求编号和 commitId；不把多个 Git 根目录合并为一个 commit。

没有独立规则的外部目录如果需要维护进度，应在其自身根目录维护独立 `progress.md`；该记录可以继承父项目的规则格式，但父项目 `progress.md` 只记录父项目文件。

## 父项目关联目录章节

父项目 `AGENTS.md` 的托管区可使用以下章节登记外部目录：

```markdown
## 6. 关联工作目录

| 名称 | 路径 | 用途 | 规则来源 | 维护方式 |
| --- | --- | --- | --- | --- |
| 工作目录 A | `D:/code/project-a` | 业务模块 | 外部 `AGENTS.md` | 单独维护 |
| 工作目录 B | `D:/code/project-b` | 公共服务 | 继承父项目规则 | 按需编辑 |
```

如果没有已确认的关联目录，写明“无已登记关联工作目录”，不要猜测外部路径。

## 汇报要求

最终结果按项目根目录分组报告：

- 当前根目录：规则来源、分析结果、修改文件、文档同步和提交状态；
- 每个外部目录：路径、是否存在独立规则、受限分析结论、是否实际编辑、修改文件和独立提交状态；
- 未编辑的外部目录明确写“仅分析，未修改”；
- 无规则文件的目录明确写“继承父项目规则”；
- 有候选冲突或路径缺失时列出阻断原因和需要用户补充的内容。
