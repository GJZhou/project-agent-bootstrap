# 文档清单与进度格式

## 文档清单

`docs/文档清单.md` 使用托管区标记保存自动维护的文档表：

```markdown
# 文档清单说明

<!-- project-agent-bootstrap:managed:start -->
| 文档路径 | 文档名称 | 用途 | 状态 |
| --- | --- | --- | --- |
| `docs/xxx.md` | 示例文档 | 说明文档用途 | 有效 |
<!-- project-agent-bootstrap:managed:end -->
```

每次运行只刷新标记范围内的表格，保留标记外的用户说明、补充清单和备注。清单应覆盖项目内可识别的纯文档；优先读取根目录和 `docs/` 的直接内容，不扫描构建产物、缓存、依赖包或脚本配套文档。

文档清单以当前项目根目录为边界。外部关联目录的文档清单、配套文档和 `progress.md` 在外部目录内独立维护：

- 父项目只登记外部目录及其文档管理状态，不把外部文档复制到父项目清单；
- 外部目录有自己的 `AGENTS.md` 时，遵循其文档位置和清单规则；
- 外部目录没有自己的 `AGENTS.md`、且本次明确编辑该目录时，继承父项目文档规则并在外部目录内维护必要记录；
- 外部目录仅被分析、未被编辑时，不创建或修改其文档清单和进度文件；
- 已有文档保留原位置，不因清单刷新自动移动、重命名或删除。

首次创建 `docs/` 时，在 `.gitignore` 中加入整个 `docs/`；已有 `docs/` 不因校验而强制改变忽略策略。

## 初始化 `progress.md`

手动配置项必须位于文件顶部并原样保留，即使当前需求编号为空：

```markdown
版本号：请手动配置
当前需求编号：

<!-- project-agent-bootstrap:managed:start -->
## 项目进度记录

暂无非文档类变更记录。
<!-- project-agent-bootstrap:managed:end -->
```

旧版没有进度托管标记时，将自动维护的 `## 项目进度记录` 及其版本章节包裹到标记中；无法安全识别时保留原文并报告。

## 按版本聚合提交

Git 项目完成本地 commit 后，在当前版本章节下追加：

```markdown
## 版本 1.0.0

### 提交 1

- 类型：ADD
- 修改用途：新增用户权限同步能力
- 修改文件：
  - src/authority/AuthoritySyncService.java
- commitId：abc1234

### 提交 2

- 类型：MOD
- 修改用途：调整权限同步失败处理逻辑
- 修改文件：
  - src/authority/AuthoritySyncService.java
- commitId：def5678
```

维护规则：

1. 读取顶部当前版本号。
2. 找到对应的 `## 版本 <版本号>` 章节；不存在时创建。
3. 在该版本章节末尾追加下一个提交编号。
4. 记录实际类型、用途、文件清单和真实 commitId；不要在每条提交中重复版本号。
5. 需求编号为空时不创建没有真实 commit 的 Git 提交记录。

父项目和外部关联目录分别读取各自的版本号、需求编号和进度文件。外部目录产生的提交记录只能写入外部目录的 `progress.md`，不能写入父项目进度章节；父项目进度只记录父项目根目录文件。

非 Git 项目如果本次确实更新了项目规则或文档，可以追加文档同步记录：

```markdown
### 记录 1

- 类型：DOC
- 修改用途：项目资料更新
- 修改文件：
  - AGENTS.md
  - docs/文档清单.md
- commitId：N/A（非 Git 项目）
```

非 Git 项目不伪造代码提交。没有内容变化时不追加重复记录，只报告已检查且无变化。
