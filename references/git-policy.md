# Git 安全与本地提交流程

## 阶段边界

文档与规则同步是独立的 Phase A，始终执行。Git 提交是独立的 Phase B，只处理非文档变更；需求编号为空只能阻止 Phase B，不能阻止 Phase A。

## 项目识别

仅当项目根目录存在 `.git` 目录或 Git 文件时启用自动提交。非 Git 项目跳过全部 commit 逻辑，但仍必须维护 `AGENTS.md`、`progress.md`、`docs/文档清单.md` 和必要的 `.gitignore`。

父项目和外部关联目录分别识别自己的 Git 根目录。外部目录有独立 `AGENTS.md` 时使用其提交规则；没有时继承父项目提交规则。每个 Git 根目录只暂存和提交属于自己的当前任务文件，不把父项目和外部目录合并为一个 commit。

## 远端边界

以下操作及同类操作都属于远端操作，必须先获得用户明确确认：

- `git push`、`git pull`、`git fetch`、`git clone`。
- 修改 remote URL、设置或改变 upstream、远端分支同步和发布标签。
- 任何可能访问网络上的 Git 服务的命令。

本地 `status`、`diff`、`log`、`add`、`commit` 可以在用户已授权的工作范围内执行；本地 commit 不等于允许 push。

## Phase B 提交条件

仅在以下条件同时满足时自动提交：

1. 当前目录是 Git 项目。
2. 本次存在非文档文件变更。
3. `progress.md` 顶部需求编号已配置且不是空值或初始化占位值。
4. 当前任务允许自动本地提交。

若需求编号为空或仍为占位值：

- 保留 Phase A 已完成的文件更新。
- 不执行 `git add` 或 `git commit`。
- 最终报告已更新的规则/文档文件、未提交的非文档文件和需要配置的需求编号。

## 提交和记录

1. 只收集当前任务实际修改的非文档文件，排除用户已有的无关改动。
2. 新功能选择 `ADD`，已有功能迭代选择 `MOD`；混合批次统一使用 `MOD`。
3. 提交消息格式为 `ADD 需求编号 提交内容summary` 或 `MOD 需求编号 提交内容summary`。
4. 取得真实 commitId 后，按 [docs-and-progress.md](docs-and-progress.md) 写入当前版本记录。
5. 不执行第二次提交，也不执行 push；被忽略的 `AGENTS.md` 和 `progress.md` 不因此停止更新。

`.gitignore` 的修改属于非文档文件；在具备提交条件时纳入当前批次，否则只保留工作区更新并报告原因。

## 跨项目变更报告

当一次任务修改多个项目根目录时，最终报告按根目录分别列出：

- 规则来源（外部规则或继承父项目规则）；
- 修改文件清单；
- 是否为 Git 项目；
- commit 类型、commitId 或未提交原因；
- 对应的 `progress.md` 是否已更新。

外部目录只被分析而未编辑时，明确报告“仅分析，未修改”。
